# Event Tracking API

## Account (API Client)

- Create account with:
    - `login` for admin panel access
    - `password_hash` (hashed with bcrypt, includes salt internally)
    - `name` (application name)
    - `email` (contact email)
- Update account fields:
    - `name`
    - `email`
    - `password_hash`
- Delete account
- Retrieve account by:
    - `id`
    - `login`
- Password verification handled at service layer (not repository)
- All sensitive data (passwords) stored only as hashed strings

## API Key

- Generate new API Key for an account
- Deactivate existing API Key
- Delete API Key
- List all API Keys for an account
- Each API Key is strictly linked to one Account
- Only authorized users (logged-in account admins) can manage keys
- API Key used for authentication when sending events

## Event

- Record event with:
    - `account_id` (owner of the event)
    - `user` (string identifier generated by account)
    - `api_key_id` (key used to send event)
    - `name` (event name)
    - `payload` (optional JSON data)
    - `created_at` (timestamp of event)
- Events stored as-is; payload is opaque to the system
- Query/filter events by:
    - `account_id`
    - `user`
    - `api_key_id`

## Interaction Flow

1. Admin creates an **Account** via admin panel.
2. Admin generates one or multiple **API Keys** for the account.
3. Application uses API Key to send events to the system.
4. System validates API Key and stores the event.
5. Admin can query events by account, user, or API Key for analytics.
